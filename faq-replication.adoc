= NetApp Replication 관련 FAQ

:allow-uri-read: 
:nofooter: 
:icons: font

[role="lead"]
이 FAQ는 NetApp Replication에 대한 일반적인 질문에 답변합니다. ONTAP 시스템, Cloud Volumes ONTAP 및 Amazon FSx for ONTAP 간의 복제 관계를 설정, 관리 및 문제 해결할 때 유용한 개념, 용어 및 동작에 중점을 둡니다.



[[general-concepts]]
== 일반적인 개념

.복제는 어떤 소스 및 대상 시스템 조합을 지원합니까?
복제는 Amazon FSx for ONTAP, Cloud Volumes ONTAP 및 온프레미스 ONTAP를 지원합니다. 세 시스템 중 어느 시스템 간에도 복제를 구성할 수 있습니다.

.Replication은 어떤 데이터 보호 구성을 지원합니까?
복제는 세 가지 구성을 지원합니다.

* *Simple*: 복제는 A 볼륨에서 B 볼륨으로 이루어집니다.
* *팬아웃*: 볼륨 A에서 여러 대상으로 복제가 수행됩니다.
* *캐스케이드*: 복제는 A 볼륨에서 B 볼륨으로, 그리고 B 볼륨에서 C 볼륨으로 발생합니다.


.최초 복제 전송과 이후 전송 과정에서 발생하는 차이점은 무엇입니까?
기본 전송에는 원본 데이터의 전체 복사본이 포함됩니다. 이후 전송에는 원본 데이터의 차등(증분) 복사본만 포함됩니다.

.Replication 사용에 비용이 드나요?
NetApp은 복제 기능 자체 사용에 대해서는 요금을 부과하지 않지만, 클라우드 공급업체에 데이터 수신 및 송신 요금에 대해 문의해야 합니다. NetApp Console은 스토리지 시스템 또는 데이터 서비스에 연결하기 위해 콘솔 에이전트를 배포할 때 요금이 부과되며, Console에서 액세스할 수 있는 일부 NetApp 데이터 서비스는 라이선스 또는 구독 기반입니다.

.Replication 기능을 사용하려면 라이센스나 구독이 필요합니까?
Console 또는 Replication 사용을 시작하는 데 라이센스나 구독이 필요하지 않습니다. 온프레미스 ONTAP 구성의 경우, 활성화된 SnapMirror 라이센스가 설치되어 있어야 합니다.



[[replication-policies]]
== 복제 정책

.미러 정책과 백업 정책의 차이점은 무엇입니까?
복제 정책에는 세 가지 유형이 있습니다.

* *미러링*: 새로 생성된 스냅샷 복사본을 타겟 볼륨으로 복제합니다. 재해 복구 준비 또는 일회성 데이터 복제에 유용하며, 언제든지 타겟 볼륨을 데이터 액세스를 위해 활성화할 수 있습니다.
* *백업*: 특정 레이블이 지정된 스냅샷 복사본을 대상 볼륨으로 복제하며, 일반적으로 원본 볼륨보다 더 오랫동안 보존합니다. 손상되거나 손실된 데이터를 복원하거나 규정 준수/관리 목적으로 유용합니다.
* *Mirror and Backup*: 재해 복구와 장기 보존 기능을 모두 포함하며, 모든 시스템에 기본적으로 제공되는 정책입니다.


기본 정책이 요구 사항을 충족하지 못하는 경우 System Manager를 사용하여 사용자 지정 정책을 만들 수 있습니다.

.내 백업 정책이 스냅샷 복사본을 복제하지 않는 이유는 무엇입니까?
백업 정책은 소스 볼륨의 스냅샷 정책에 정의된 레이블과 일치하는 스냅샷 복사본만 복제합니다. 사용자 지정 백업 정책의 레이블이 스냅샷 정책의 어떤 레이블과도 일치하지 않으면 시스템에서 스냅샷 복사본을 복제할 수 없습니다. 예를 들어 "daily" 및 "weekly" 레이블이 있는 백업 정책은 해당 레이블이 있는 스냅샷 복사본만 복제합니다.

.기본 정책을 사용할 경우 기본 스냅샷 보존 설정은 어떻게 됩니까?
기본 스냅샷 정책은 시간별, 일별, 주별 스냅샷 복사본을 생성하며, 시간별 복사본 6개, 일별 복사본 2개, 주별 복사본 2개를 보존합니다. 기본 백업 정책은 일별 및 주별 스냅샷 복사본을 복제하며, 일별 스냅샷 복사본 7개와 주별 스냅샷 복사본 52개를 보존합니다.



[[setting-up-replication]]
== 복제 설정

.데이터 복제를 설정하기 전에 무엇을 확인해야 하나요?
데이터를 복제하기 전에 다음 사항을 확인하십시오.

* 소스 시스템과 타겟 시스템이 이미 존재합니다(또는 생성합니다).
* 원본 및 대상 볼륨이 호환되는 ONTAP 버전을 실행 중인지 확인하십시오. link:https://docs.netapp.com/us-en/ontap/data-protection/compatible-ontap-versions-snapmirror-concept.html["호환되는 ONTAP 버전"^]을 참조하십시오.
* 시스템별 요구 사항을 충족했는지 확인하십시오link:task-replicating-data.html["데이터 복제 요구 사항"].


.클러스터 간 LIF에서 클러스터 피어링이 올바르게 작동하려면 무엇이 필요합니까?
클러스터 간 네트워크는 클러스터 피어 간에 쌍별 풀 메시 연결이 이루어지도록 구성해야 합니다. 즉, 클러스터 피어 관계에 있는 각 클러스터 쌍은 모든 클러스터 간 LIF 간에 연결성을 가져야 합니다. 이는 여러 개의 LIF를 가진 ONTAP 클러스터가 소스 또는 타겟인 경우에 적용됩니다.

.사용자 지정 복제 일정을 만들 수 있나요?
복제를 설정할 때 몇 가지 기본 일정이 제공됩니다. 다른 일정을 사용하려면 System Manager를 사용하여 타겟 클러스터에서 새 일정을 생성해야 합니다.



[[managing-replication-relationships]]
== 복제 관계 관리

.복제 관계가 유휴 상태이고 미러 상태가 초기화되지 않은 것으로 표시되는 경우 이는 무엇을 의미합니까?
이는 타겟 시스템에 장애가 발생했다가 다시 온라인 상태가 될 때 발생할 수 있습니다. 데이터 복제가 정의된 일정에 따라 재개되도록 하려면 System Manager 또는 CLI를 사용하여 타겟 시스템에서 관계를 초기화해야 합니다.

.중단, 재동기화 및 역재동기화 작업의 차이점은 무엇입니까?
이러한 작업들은 각기 다른 효과를 가져옵니다.

* *Break*: 소스 볼륨과 대상 볼륨 간의 관계를 끊고 대상 볼륨을 데이터 액세스에 활성화합니다. 일반적으로 소스 볼륨이 손상, 삭제 또는 오프라인 상태로 인해 데이터를 제공할 수 없을 때 사용됩니다.
* *재동기화*: 끊어진 관계를 다시 설정하고 예정된 시간에 복제를 재개합니다. 타겟 볼륨의 내용은 소스 볼륨의 내용으로 덮어씁니다.
* *역방향 재동기화*: 소스 볼륨과 대상 볼륨의 역할을 반전시켜 원래 소스 볼륨의 내용을 대상 볼륨의 내용으로 덮어씁니다. 마지막 복제 시점과 소스 볼륨이 오프라인 상태가 된 시점 사이에 원래 소스 볼륨에 기록된 데이터는 보존되지 않습니다.


.복제 관계를 삭제하면 어떻게 됩니까?
원본 볼륨과 대상 볼륨 간의 데이터 보호 관계를 삭제하면 볼륨 간 데이터 복제가 종료되고, 대상 사이트에서 SnapMirror 관계가 삭제되며, 원본 사이트에서 관계가 해제됩니다. 또한 SnapMirror 관계가 해제되어 대상 볼륨이 잠시 읽기/쓰기 작업의 기본 사이트가 되므로 복제가 제거된 후 대상 볼륨을 독립적으로 사용할 수 있습니다.

.최대 전송 속도를 무제한으로 두는 대신 제한해야 하는 이유는 무엇입니까?
무제한 전송 속도는 다른 애플리케이션 및 인터넷 성능에 부정적인 영향을 미칠 수 있습니다. 복제를 설정할 때 최대 전송 속도(초당 메가바이트 단위)를 제한해야 하며, 복제 상태 페이지에서 나중에 수정할 수 있습니다.
